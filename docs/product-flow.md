# 제품 흐름 (탐색 → 라이브러리 → 재생목록)

이 문서는 화면/라우트를 짜기 전에 확정된 도메인 흐름을 적어둔 것입니다. 세부 정책 중 아직
정해지지 않은 부분은 "미정"으로 표시해뒀고, 결정되면 이 문서를 갱신하세요.

## 핵심 흐름

1. **탐색(Explore)**: 사용자가 YouTube Data API로 곡을 검색합니다(`api/youtube-search.ts`
   프록시 경유 — 이 함수 하나가 검색과 영상 상세 조회를 함께 처리합니다). 검색 결과에서
   태그를 지정해 추가하면 `tracks`
   테이블에 저장됩니다 — 이 시점부터 "라이브러리"의 일부가 됩니다.
2. **라이브러리(Library)**: 탐색을 통해 추가된 곡들이 모이는 곳입니다. 헤더의 "라이브러리
   내 검색"으로 제목/아티스트/태그 기준으로 찾을 수 있습니다 — 지금은 불러온 라이브러리
   전체를 브라우저에서 거릅니다(DB 쪽 trigram/GIN 인덱스는 `docs/db-schema.md` 참고).
3. **재생목록(Playlist)**: 라이브러리의 곡들을 모아 재생목록을 만들고 곡을 추가/제거/재정렬할
   수 있습니다(`playlists` + `playlist_tracks`, `position` 컬럼으로 순서 관리).
4. **재생(Playback)**: 사용자는 재생목록 전체를 재생할 수도 있고, 라이브러리에서 곡 하나만
   골라 단일 재생할 수도 있습니다. 이 구분은 old-src의 `playSingle` / `playPlaylist`
   흐름과 동일한 개념입니다(`old-src/src/Home.js` 참고 — 로직 자체는 재사용하지 않지만
   개념은 그대로 가져옴).

## 접근 권한

- **비회원(로그인 안 한 사용자)**: `/`에서 랜딩 페이지(`src/features/landing/`)만 볼 수
  있습니다. 랜딩에서는 YouTube 검색과 단일 곡 재생(게스트 재생 — 검색어·재생 기록을
  저장하지 않음)을 해볼 수 있고, 라이브러리·탐색(곡 추가)·재생목록 등 나머지 화면은
  로그인이 필요합니다(보호된 주소로 바로 들어오면 `/login`으로 이동).
- 이 범위를 바꾸면 이 문서와 `src/router/`의 가드(`HomeAccessGate`/`RequireAuth`/
  `GuestOnly`) 적용 범위를 함께 갱신하세요. 라우트 구조는 `docs/architecture.md`의
  "인증과 라우팅"을 참고하세요.

## 라우트/화면 설계에 영향을 주는 점

- "탐색"과 "라이브러리"는 old-src에서는 한 화면(`SearchMusic.js`) 안의 검색 대 추가 흐름에
  가까웠지만, 새 디자인(`docs/design/`)에서는 명확히 분리된 두 개의 탭이라 라우트도
  라이브러리(`/`)와 탐색(`/explore`)으로 나눴습니다.
- 단일 곡 재생과 재생목록 재생이 공존하므로, 플레이어 상태(`src/features/player/lib/usePlayerStore.ts`)가
  `playingPlaylistId`(단일 곡 재생이면 `null`)로 "지금 재생목록 재생 중인지 vs 단일 곡 재생
  중인지"를 구분합니다.
