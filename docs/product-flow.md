# 제품 흐름 (탐색 → 라이브러리 → 재생목록)

이 문서는 화면/라우트를 짜기 전에 확정된 도메인 흐름을 적어둔 것입니다. 세부 정책 중 아직
정해지지 않은 부분은 "미정"으로 표시해뒀고, 결정되면 이 문서를 갱신하세요.

## 핵심 흐름

1. **탐색(Explore)**: 사용자가 YouTube Data API로 곡을 검색합니다(`api/youtube-search.ts`,
   `api/youtube-video.ts` 프록시 경유). 검색 결과에서 태그를 지정해 추가하면 `tracks`
   테이블에 저장됩니다 — 이 시점부터 "라이브러리"의 일부가 됩니다.
2. **라이브러리(Library)**: 탐색을 통해 추가된 곡들이 모이는 곳입니다. 라이브러리 내
   검색창으로 제목/아티스트/태그 기준으로 필터링할 수 있습니다(Supabase
   `tracks` 테이블 + trigram/GIN 인덱스 활용, `docs/migrations/0001_init.sql` 참고).
3. **재생목록(Playlist)**: 라이브러리의 곡들을 모아 재생목록을 만들고 곡을 추가/제거/재정렬할
   수 있습니다(`playlists` + `playlist_tracks`, `position` 컬럼으로 순서 관리).
4. **재생(Playback)**: 사용자는 재생목록 전체를 재생할 수도 있고, 라이브러리에서 곡 하나만
   골라 단일 재생할 수도 있습니다. 이 구분은 old-src의 `playSingle` / `playPlaylist`
   흐름과 동일한 개념입니다(`old-src/src/Home.js` 참고 — 로직 자체는 재사용하지 않지만
   개념은 그대로 가져옴).

## 접근 권한

- **비회원(로그인 안 한 사용자)**: 단일 곡 재생만 허용됩니다. 재생목록 재생, 탐색을 통한
  추가, 라이브러리에 곡 추가 등은 로그인이 필요할 가능성이 높습니다.
- 비회원에게 정확히 어디까지 허용할지(예: 탐색 자체는 가능한지, 라이브러리 열람이
  가능한지 등)는 **미정**입니다 — 정해지면 이 문서와 `RequireAuth`/`GuestOnly` 가드
  적용 범위를 함께 갱신하세요.

## 라우트/화면 설계에 영향을 주는 점

- "탐색"과 "라이브러리"는 old-src에서는 한 화면(`SearchMusic.js`) 안의 검색 대 추가 흐름에
  가까웠지만, 새 디자인(`docs/design/`)에서는 명확히 분리된 두 개의 탭입니다. 새 라우트
  구조를 정할 때 이 탭 분리를 반영해야 합니다.
- 단일 곡 재생과 재생목록 재생이 공존하므로, 플레이어 상태(`src/stores/usePlayerStore.ts`)가
  "지금 재생목록 재생 중인지 vs 단일 곡 재생 중인지"를 구분할 수 있어야 합니다.
