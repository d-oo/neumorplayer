`git status`, `git diff`(스테이징 여부 상관없이 전부), 그리고 이 저장소의 기존 스타일
파악을 위해 `git log`를 확인한 뒤 커밋 메시지를 작성합니다.

## 하지 말 것

- `git add`, `git commit`, `git stash` 등 실제로 작업 트리/히스토리를 바꾸는 명령은
  **절대 실행하지 않습니다.** 메시지만 만들어서 보여주고, 커밋은 사용자가 직접
  합니다.

## 메시지 작성 규칙

- **핵심만 남깁니다.** "무엇이 왜 바뀌었는지" 한 줄 요약 + 불릿 몇 개 수준으로
  정리하고, 세부 구현 디테일(어떤 함수/컴포넌트를 썼는지, 값이 몇 px인지, 어떤
  라이브러리를 썼는지 같은 것)은 뺍니다.
- 이 저장소 `git log`의 기존 스타일(한 줄 요약 제목 + 하이픈 불릿, 한국어)을
  그대로 따릅니다.
- 작업 트리에 이번 요청과 무관한 변경(세션에서 건드리지 않은 파일, 다른 작업의
  흔적)이 섞여 있으면, 그건 메시지에 포함하지 말고 있다는 사실만 짧게 언급합니다.
- 결과는 그대로 복사해 쓸 수 있게 코드 블록 하나로 보여줍니다.
